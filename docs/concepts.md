# 채팅 기능 기본 개념과 로직

## 개요

본 프로젝트에서는 채팅 기능 제작에 필요한 기본 개념과 로직을 설명합니다. 채팅 기능은 현대 웹/앱 애플리케이션의 핵심 기능 중 하나로, 실시간 소통을 가능하게 하는 중요한 요소입니다.

## 용어 및 표기법

### 약어
- **RTDB (Realtime Database)**: Firebase Realtime Database를 짧게 표현한 약어입니다. 본 문서에서는 RTDB로 표기합니다.

### RTDB 노드 용어
RTDB의 각 노드는 상황에 따라 다음과 같이 부릅니다:
- **문서**: 특정 경로의 데이터 전체를 지칭할 때
- **값**: 단순 값(문자열, 숫자 등)을 가리킬 때
- **노드**: 트리 구조에서 특정 위치를 가리킬 때
- **데이터**: 일반적인 정보를 지칭할 때

각 문서는 맵(객체)의 형태로 "키", "값" 쌍으로 구성됩니다.

### 변수 표기법
문서에서 변수 값의 표시는 `<변수명>` 형식으로 표시합니다. 즉, `<`와 `>` 사이에 값이 들어가면 변수로 동적인 값이 들어간다는 뜻입니다.

예시:
- `<uid>`: 사용자 고유 ID
- `<roomId>`: 채팅방 ID
- `<messageId>`: 메시지 ID
- `<timestamp>`: 타임스탬프 값

## 채팅 기능의 핵심 개념

### 1. 실시간 통신 (Real-time Communication)
- **WebSocket**: 양방향 실시간 통신 프로토콜
- **Long Polling**: WebSocket을 사용할 수 없는 환경을 위한 대안
- **Server-Sent Events (SSE)**: 서버에서 클라이언트로의 단방향 실시간 통신

### 2. 메시지 전송 흐름
```
사용자 입력 → 클라이언트 검증 → 서버 전송 → 서버 검증 및 저장 →
브로드캐스트 → 수신자 클라이언트 → UI 업데이트
```

### 3. 채팅방 관리
- **1:1 채팅**: 두 사용자 간의 개인 대화
- **그룹 채팅**: 여러 사용자가 참여하는 단체 대화
- **채널/방 개념**: 대화를 구분하는 논리적 단위

### 4. 메시지 타입
- **텍스트 메시지**: 기본 문자 메시지
- **미디어 메시지**: 이미지, 동영상, 음성
- **파일 첨부**: 문서, 압축 파일 등
- **시스템 메시지**: 입장/퇴장, 공지사항 등

### 5. 사용자 상태 관리
- **온라인/오프라인 상태**: 실시간 접속 상태 표시
- **읽음 확인**: 메시지 읽음 여부 추적
- **타이핑 인디케이터**: 상대방이 입력 중임을 표시

## 기본 로직 구현

### 메시지 전송 로직
```javascript
// Alpine.js 예제
function sendMessage() {
    // 1. 입력 검증
    if (!message.trim()) return;

    // 2. 메시지 객체 생성
    const messageData = {
        text: message,
        sender: currentUser.id,
        timestamp: Date.now(),
        roomId: currentRoom.id
    };

    // 3. 서버로 전송
    socket.emit('message', messageData);

    // 4. UI 즉시 업데이트 (낙관적 업데이트)
    addMessageToUI(messageData);

    // 5. 입력 필드 초기화
    clearInput();
}
```

### 메시지 수신 로직
```dart
// Flutter 예제
void _listenToMessages() {
  socket.on('message', (data) {
    setState(() {
      messages.add(Message.fromJson(data));
    });

    // 자동 스크롤
    _scrollToBottom();

    // 읽음 확인 전송
    _markAsRead(data['id']);
  });
}
```

## 데이터베이스 구조

채팅 애플리케이션에서 데이터를 효율적으로 저장하고 관리하기 위해서는 체계적인 데이터베이스 구조가 필요합니다. Firebase Realtime Database를 사용하는 경우의 데이터 구조와 접근 방법에 대한 상세한 내용은 [데이터베이스 구조 문서](./database-structure.md)를 참고하세요.

## 데이터 동기화

### 오프라인 지원
- 로컬 캐싱을 통한 오프라인 메시지 읽기
- 재연결 시 미전송 메시지 자동 전송
- 충돌 해결 전략

### 메시지 순서 보장
- 타임스탬프 기반 정렬
- 메시지 ID를 통한 중복 제거
- 낙관적 업데이트와 서버 응답 동기화

## 보안 고려사항

### 인증 및 권한
- 사용자 인증 토큰 검증
- 채팅방 접근 권한 확인
- 메시지 전송 권한 검증

### 데이터 보호
- 메시지 암호화 (End-to-End Encryption)
- XSS 공격 방지 (입력 값 검증 및 이스케이핑)
- SQL Injection 방지
